# KRDS 디지털 포용(접근성) 규칙 스냅샷

출처: https://www.krds.go.kr/html/site/utility/utility_04.html
수집일: 2026-07-25 (내용이 바뀐 것 같으면 사용자에게 "규칙 갱신"을 요청해 WebFetch로 재수집할 것)

준수 기준: KWCAG 2.2, 전자정부 웹사이트 품질관리 지침, WCAG 2.1. "KRDS 적용만으로는 완벽한 접근성을 보장할 수 없으며, 지속적인 노력이 필요하다"고 원문에 명시되어 있음.

## A. 자동 검증 가능 항목 (이 스킬이 실제로 계산/판정한다)

### A-1. 명도 대비 (Contrast Ratio)
- **텍스트 콘텐츠**: 전경/배경 대비 **4.5:1 이상** (WCAG AA)
- **비텍스트 콘텐츠**(아이콘, 그래픽 요소, 셀렉트 아이콘-배경, 입력 필드 포커스 테두리 등): **3:1 이상**
- **선명한 화면 모드(고대비 모드)**: 정보 전달용 글자/배경/그래픽 요소 간 대비 **4.5:1 이상**
- 계산 방법: WCAG relative luminance 공식으로 두 색의 대비율을 계산 (`krds_check.py` 참고)
- 전경/배경 페어를 신뢰성 있게 특정할 수 없는 노드는 계산하지 않고 "대비 계산 불가 — 수동 확인 필요"로 분류한다 (억지로 추정하지 않음)

### A-2. 색상 단독 정보 구분 금지 (추정 판정)
- 원문 규칙: "색상만으로 정보 구분 금지" (색각이상자·색약자 고려), 라디오/체크박스는 "선택 상태를 색상 외 다른 수단으로도 표현"
- 자동 추정 방법(휴리스틱, 100% 확정 아님): 같은 컴포넌트의 상태 variant(예: default/selected/error)들이 fill 색상값만 다르고, 텍스트 라벨·아이콘·보더 스타일 등 비색상 속성이 모두 동일하면 "색상 단독 구분 의심" 으로 플래그. 확정 판정이 아니므로 리포트에 "추정치, 스크린샷으로 육안 확인 권장"이라고 표기한다.

## B. 스코프 밖 항목 (Figma 정적 디자인만으로는 검증 불가 — 리포트에 출력하지 않음)

이 항목들은 코드 구현/동작 단계에서만 확인 가능한 상호작용·행동 규칙이라 깨미의 검사 범위 밖이다. 원문 스냅샷 참고용으로만 남겨두며, 리포트에는 포함하지 않는다.

- **헤더/푸터**: 건너뛰기 링크 제공 여부, 로고 대체 텍스트
- **메뉴**: 키보드 탐색 가능 여부, 활성화 상태의 프로그래밍적 명시
- **이미지**: 장식용 제외 모든 이미지의 대체 텍스트 존재 여부
- **버튼**: 접근 가능한 이름(accessible name) 제공, 키보드 조작 가능 여부
- **폼 입력**: 레이블 연결, `autocomplete` 속성 설정, 오류 메시지의 프로그래밍적 연결
- **표**: 데이터 구조 마크업(th/scope 등), 반응형 스크롤 동작
- **캐러셀**: 자동재생 정지 버튼이 포커스 순서상 첫 번째 요소인지, 키보드 탐색 지원
- **탭/모달**: 포커스 이동 순서, 키보드 포커스 트랩 방지
- **입력 폼 전반**: 자동 초점 이동(에러 시), 입력값 유지
- **멀티미디어**: 자막, 음성 해설 제공 여부
- **음성지원**: 화면 텍스트 음성 출력이 보완 수단으로 존재하는지 (대체 수단 아님)
- **화면 크기 조정**: 텍스트 확대/축소 시 콘텐츠 손실 방지, 단일 방향 스크롤 유지
- **언어 변경**: 일관된 언어 전환 제공 여부

## C. 리포트 표기 규칙

- A 항목은 실제 계산 결과(Pass/Fail, 수치)를 표로 제시한다.
- B 항목은 리포트에 언급하지 않는다.
